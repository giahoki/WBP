# Загрузчик и рантайм (`src/`)

`wbp-game.exe` — это и есть игра. Он загружает подготовленный лаунчером образ, подключает вместо
системных библиотек PS4 свой рантайм, поднимает графику и передаёт управление коду игры.

## Образ игры

`eboot.bin` в дампе — это расшифрованный PS4 SELF (ELF внутри обёртки Sony). Лаунчер
(`launcher/src/prep/image.cpp`) один раз превращает его в плоский образ памяти
`out\boot-linked.bin` (формат `BBPROBE5`) и кэширует по размерам и датам файлов:

1. Сегменты SELF раскладываются по программным заголовкам ELF; все смещения проверяются.
2. Загружаемые сегменты копируются в образ по их виртуальным адресам (база eboot — 0).
3. Таблицы релокаций разбираются: относительные (`R_X86_64_RELATIVE`) остаются загрузчику,
   ссылки на внешние функции становятся импортами по имени (NID — хэш имени SHA-1 по правилам
   Sony).
4. После eboot в тот же образ кладутся `sce_module\libc.prx` и `libSceFios2.prx` из дампа: их
   экспорты связываются с импортами игры напрямую, и эти функции тоже выполняются нативно.
5. Инструкции `mov rax, fs:[0]` (чтение указателя потока) переписываются на `gs:`.
6. Проверяется, что `_init_env` в libc — ровно `RET` (иначе запуск небезопасен).

Остальные импорты (около 500) обслуживает рантайм.

## Запуск (`probe.c`)

1. Резервируется диапазон адресов PS4 (64 ГиБ – 1 ТиБ), чтобы туда не попали драйвер видеокарты
   и кучи Windows: адреса GPU в PS4 — 40-битные.
2. Читаются `content.bin` (профиль AppContent), `patches.bin`, папки игры и пользователя.
3. Образ отображается в память, применяются релокации. Импорты, не связанные с libc, получают
   переходники на функции рантайма; неизвестная функция останавливает игру с её именем
   (`--strict-imports`), а не «тихо» возвращает ноль.
4. Применяются патчи (`BBPATCH2`): побайтные записи по адресам 1.09; указатели в
   релоцируемых ячейках переносятся на реальный адрес образа.
5. Ставится хук мышиной камеры ([INPUT.md](INPUT.md)).
6. Чтение TCB `gs:[0]` переписывается на слот TLS в TEB Windows: регистр GS в Windows занят TEB и
   не перемещается, поэтому TCB гостевого потока хранится в `TlsSlots[slot]`.
7. Поднимается графика (`bbgpu_init`), запускаются инициализаторы libc и Fios2, затем точка входа
   игры на собственном стеке ниже 1 ТиБ. В журнале: `Entering original x86-64 code`.

## Исключения

Векторный обработчик исключений (`vectored_fault`) отвечает на три случая:

- **Запись в отслеживаемую память.** Графика защищает страницы, из которых она взяла буферы и
  текстуры; первая запись игры вызывает исключение, графика помечает данные «грязными»,
  открывает окно в 64 КБ вокруг и продолжает поток.
- **Спекулятивное чтение потока подготовки отрисовки** наткнулось на неотображённую память: поток
  возвращается в точку восстановления (`bb_longjmp`, без раскрутки стека).
- **Настоящий сбой** в коде игры, загрузчика или рантайма: отчёт в журнал (регистры, модуль, адрес)
  и завершение. Исключения драйверов и системных библиотек обрабатывают они сами.

Код выхода игры записывается в журнал строкой `wbp-game exited with code …` с расшифровкой
(например, `0xC0000005: crash: access violation`).

## Рантайм

Каждый модуль — явный контракт под то, что вызывает Bloodborne; заглушек «всегда успех» нет.

| Модуль | Что делает |
|---|---|
| `runtime_memory.c` | память PS4: прямая (физическая) память, гибкая память, резервирования, защита. В Windows — секция в файле подкачки и плейсхолдеры (`VirtualAlloc2`/`MapViewOfFile3`), как в shadPS4 |
| `runtime_thread.c` | потоки PS4 на pthreads, TCB с TLS (вариант II FreeBSD), приоритеты записываются, но не навязываются |
| `runtime_mutex.c`, `runtime_rwlock.c`, `runtime_sema.c` | мьютексы, rwlock, семафоры, события |
| `runtime_kernel.c`, `runtime_time.c`, `runtime_rtc.c` | часы, сон (точные таймеры Windows), errno в нумерации FreeBSD, sysctl |
| `runtime_file.c` | файлы: `/app0` → папка игры (или оверлей модов), `/temp0`, `/data` и точки сохранений → папка пользователя; пути с `..` отклоняются |
| `runtime_savedata.c` | сохранения в `user\savedata\<пользователь>\<игра>\<папка>`, метаданные рядом |
| `runtime_audio.c` | вывод звука через SDL3 с ровным темпом: `sceAudioOutOutput` возвращается раз в период буфера, как на PS4, иначе FMOD обгоняет микшер и щёлкает |
| `runtime_ajm.c` | декодер звука AJM: ATRAC9 через LibAtrac9 |
| `runtime_pad.c`, `runtime_mouse.c` | ввод ([INPUT.md](INPUT.md)) |
| `runtime_services.c` | один локальный пользователь, сеть «выключена» (кроме онлайна через `gpu/bbnet`), диалоги, PlayGo |
| `runtime_content.c` | AppContent для базовой игры (SKU, параметры из `param.sfo`) |
| `compat_win.c` | `bb_setjmp`/`bb_longjmp` под Win64 без SEH-раскрутки и прочие замены POSIX |

## Перезапуск из игры

Смена разрешения или пресета в меню Insert требует патча при старте. Игра печатает
`restarting through the launcher`, запускает `BB_RESTART_COMMAND` (это `Bloodborne.exe --run --after
PID`) с теми же каналами вывода и завершается; новый запуск ждёт, пока старый освободит видеокарту.
